## 1. Задача

Перерисовать все иконки десктопного приложения Aura в одном современном
минималистичном стиле и добавить иконки к пунктам, где сейчас только текст.
Стиль — как на приложенном скриншоте: спокойные тонкие линейные глифы,
простые силуэты, одинаковая оптическая плотность, ничего лишнего.

Набор должен быть **строго монохромным**. Цвет — только `currentColor`.
Оранжевый акцент назначается контейнером (активный пункт, статус), а не самим SVG.

В приложение ничего не встраивать. Сначала — демонстрация, потом решение.

---

## 2. Контекст продукта

Aura — утилита голосового ввода для Windows (Tauri + Rust + веб-UI).
Окно настроек тёмное, ахроматическое: `#090909`, `#0d0d0d`, `#101010`, текст
`#f5f7fa` / `#9ba6b3`, акцент `#ff4200` (используется редко). Шрифт — Onest.

Иконки живут в трёх поверхностях:

1. **Окно настроек** — вертикальная навигация слева, карточки и строки-аккордеоны справа.
2. **Трей-меню** — компактный список 15 px.
3. **Кнопки и строки действий** — 13–16 px.

Главный критерий: пункт должен узнаваться боковым зрением на 16 px,
не споря с текстом.

---

## 3. Референс и стиль

Смотреть на приложенный скриншот «After».

Что берём:

- тонкая линия одинакового веса;
- круглые концы и стыки;
- простые геометрические силуэты: дом, документ, папка, человек, стикер;
- крупные поля внутри глифа, нет «забитости»;
- аккуратная оптическая соразмерность: ни один глиф не выглядит тяжелее соседа;
- спокойный ритм в списке.

Что не берём:

- цветные бейджи со скриншота — у нас строго моно;
- конкретные иконки Tessera 1:1 (это чужой набор, нужен свой язык);
- декор, градиенты, объём, тени, свечения;
- «милые» или игровые формы.

Чего избегать (типичные признаки «нейросетевого» набора):

- random stroke width: где-то 1.5, где-то 2.5;
- шестерёнки и прочие глифы с 20 мелкими зубцами;
- разные оптические размеры: один глиф 12 px, соседний 20 px;
- лишние внутренние линии «для детализации»;
- стоковые Lucide/Feather/Phosphor, вставленные без переработки;
- несогласованные радиусы и углы.

## 4. Жёсткие ограничения

| Параметр | Значение |
|---|---|
| viewBox | `0 0 24 24` |
| Сетка | ключевые линии 18 × 18, поля 3 px; круглые формы r = 9 |
| Штрих | 2 px, `stroke-linecap="round"`, `stroke-linejoin="round"` |
| Цвет | `currentColor` для UI-иконок; **оригинальные цвета — у знаков облачных провайдеров** |
| Заливки | только смысловые точки, треугольник Play, шкала размера модели и фирменные знаки |
| Тени / свечения | запрещены |
| Бренд-логотипы, флаги | официальные знаки NVIDIA (CUDA, Parakeet), OpenAI (Whisper), Gemini, Groq и Hugging Face разрешены; **знаки провайдеров — в оригинальных цветах**; флаги запрещены |
| Внешние библиотеки | нельзя копировать готовые наборы; пути рисуются/подгоняются вручную |
| Интеграция в `src/` | запрещена на этом этапе |

Дополнительно:

- Иконка обязана читаться на **16 px**. Если деталь исчезает — убрать деталь.
- Не должно быть двух глифов с одинаковым силуэтом в одном контексте.
- На светлом фоне набор тоже должен работать (проверить toggle в демо).
- Никакой генерации картинок: только SVG-пути.

### 5.4.1. Облачные провайдеры (4)

| Ключ | Провайдер |
|---|---|
| `provider-gemini` | Gemini |
| `provider-groq` | Groq |
| `provider-openai` | OpenAI |
| `provider-huggingface` | Hugging Face |

Официальные знаки; если приложены SVG — брать формы и **оригинальные цвета**.
Это единственное цветовое исключение в наборе. Кастомный сервер — текстом,
без иконки.

(`feGaussianBlur`); один линейный градиент даёт почти сплошную синюю заливку.
OpenAI — белый `#FFFFFF`, а не `currentColor`, иначе в селекте он наследует
серый цвет строки и становится оранжевым при наведении.

## 6. Именование и алиасы

- Ключи из раздела 5 — фиксированные. Не переименовывай их: две демонстрации
  должны сравниваться построчно, по одинаковым именам.
- Канонические имена — короткие, kebab-case: `mic`, `cloud`, `key`, `bars-3`.
- Имена поверхностей — с префиксом: `nav-*`, `tray-*`, `section-*`, `engine-*`,
  `model-*`, `filter-*`, `card-*`, `about-*`, `sound-*`, `action-*`.
- Алиасы обязательны: `nav-general → settings`, `tray-power → power` и т. д.
- В README — таблица «поверхность → канонический глиф».
- В демо-сетке показывать **канонические** имена, чтобы не было дублей.

## 7. Формат демонстрации (обязательно)

Открывается двойным кликом, без сборки и сервера (`file://`).

1. **Сетка всех иконок.** Каждая ячейка: глиф + подпись с именем.
   Показывать все канонические глифы, без пропусков.
2. **Два размера в ячейке:** 24 px (основной) и 16 px (проверка мелкого).
3. **Тёмный фон Aura** (`#090909` / `#101010`), светлый текст.
4. **Счётчик:** сколько глифов показано / всего.
5. **Фильтр по категориям** (навигация, движки, модели, действия, звук…).
6. **Переключатель 16 / 20 / 24 / 32** — по желанию, но полезно.
7. **Контекстные макеты** — сильно желательно, чтобы видеть набор в деле:
   - навигация окна настроек;
   - строка-аккордеон с иконкой в плашке;
   - карточка модели;
   - фильтры истории;
   - трей-меню;
   - строки «О программе»;
   - кнопки действий.
8. **Скриншот** демо на 1280 px в `tests/screenshots/`.
9. **Ноль ошибок в консоли.**

Минимум, без которого работа не принимается: пункты 1–4 и 8.
Макеты — то, что делает демо убедительным; лучше сделать.

## 8. Процесс работы

1. **Аудит.** Прочитать `src/index.html`, `src/tray-menu.html`, `src/style.css`
   (только чтение). Убедиться, что все слоты из раздела 5 существуют.
2. **Система.** До рисования зафиксировать: сетка, штрих, ключевые линии,
   оптические размеры, правила заливки. Записать в README.
3. **Рисование.** Порядок: навигация → утилиты → движки/модели → разделы
   и заголовки карточек → звук.
4. **Ранняя сетка.** Собрать демо-сетку после первой десятки и смотреть на 16 px.
   Не рисовать все 60 иконок «вслепую».
5. **Само-критика.** Для каждого глифа:
   - узнаётся ли на 16 px?
   - не тяжелее/легче ли соседей?
   - есть ли уникальный силуэт?
   - можно ли убрать одну деталь без потери смысла?
6. **Финал.** Скриншот, README, список решений и сомнений.

## 13. Как сравнивать две версии

Когда обе демонстрации готовы, смотреть по порядку:

1. **16 px.** Открыть сетку и контекстные макеты. Каждый глиф узнаётся без подписи?
2. **Силуэты.** На 64 px (или в `inspect`) видно, что формы разные, а не один
   трафарет с разными деталями.
3. **Вес.** Нет глифов, которые выглядят жирнее или бледнее соседей.
4. **Семейства.** Модели читаются как шкала; звуковые темы отличаются силуэтом;
   движки не путаются между собой.
5. **Контекст.** В навигации, трее и карточках иконки не спорят с текстом и
   не выглядят инородными.
6. **Покрытие.** Все слоты из раздела 5 закрыты, ничего не забыто.
7. **Демо.** Сетка с названиями, счётчик, размеры, контексты, скриншот.
8. **Признаки «нейросетевого».** Случайный штрих, мелкие зубцы, несогласованные
   радиусы, слишком много деталей.

Сравнивать не «нравится / не нравится», а по этим пунктам — тогда видно, где
именно набор выигрывает.
