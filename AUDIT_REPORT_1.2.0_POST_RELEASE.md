# Отчёт аудита Aura 2.0 — релиз 1.2.0 (post-release)

- **Дата:** 2026-10-18
- **Объект:** `G:\Aura\2.0` — приложение (`src/`, `src-tauri/`), website, winget, CI, документация
- **Базовая точка:** коммит `029fc95` (`v1.2.0`); все правки аудита — поверх него в рабочем дереве
- **Метод:** независимый статический аудит, построчная верификация исправлений, первополученный прогон всех гейтов
- **Итоговый статус:** завершён, блокеров нет; принятые остатки — раздел 6

---

## 1. Резюме и вердикт

Аудит выявил три находки высокого риска — паники границ UTF-8 в нормализаторе (`FAULT-01`, латентная `FAULT-02`) и use-after-free в Win32 DACL (`SEC-01`) — а также серию P2–P3 проблем: конкурентность (запись/игровой режим/остановка серверов), таймауты облака, защита вставки, рассинхронизация локалей команд, гигиена репозитория и CI.

**Все находки закрыты в трёх раундах исправлений и повторно верифицированы.** Финальный прогон гейтов на текущем дереве (раздел 5) полностью зелёный. Открытых блокеров нет. Единственный принятый остаток в коде — плейсхолдер `published: false` в `release-manifest-1.2.0.json` до физической сборки инсталлятора.

- **Код:** `src-tauri/src/*` (нормализация, аудио-рекордер, whisper/parakeet-раннеры, LLM-редактор, secure storage, `lib.rs`), `src/` (`main.js`, `overlay.js`, `index.html`, `overlay.html`, `style.css`).

- **Ограничение:** runtime E2E (живая диктовка, железозависимые сценарии) не выполнялся — раздел 6.

## 3. Реестр находок

### 3.1 Высокий риск

| ID | Суть | Исправление | Верификация |
|---|---|---|---|
| **FAULT-01** | Паника границы UTF-8 при нормализации префиксов субтитров: 3-байтовое тире «—» в начале текста | `text_normalizer.rs` — префиксный поиск по итератору сепараторов | Тест `test_hallucinated_em_dash_separator_no_panic_fault_01` (:2364) |
| **FAULT-02a** | Case-insensitive поиск префикса не был Unicode-safe | `find_case_insensitive` (:826) | Тест `test_case_insensitive_hallucination_unicode_safe_fault_02` (:2376) |
| **FAULT-02b** (латентная; найдена аудитором) | Паника границы символа на многоточии «…» (3 байта) в `prune_trailing_repeated_sentences` | `let end = idx + ch.len_utf8();` (:1421) | Тест `test_prune_trailing_repeated_sentences_with_ellipsis_latent_fault_02` (:2384) |
| **SEC-01** | Use-after-free: `ptr::read(TOKEN_USER)` из буфера после потери владения; риск невыровненного чтения | `secure_storage.rs` — владеемая копия SID (`owned_sid_copy`) до выхода буфера из скоупа; `read_unaligned` (:157) | Тест `atomic_write_restricts_the_dacl_to_current_user_and_system`; runtime-подтверждение (Miri/ASan) — рекомендация, раздел 7 |

### 3.2 Конкурентность (P2)

| ID | Суть | Исправление | Верификация |
|---|---|---|---|
| **CONC-01** | Игровой режим не отменял активную запись — сиротские FIFO-файлы и висящий хук ввода | Отмена активной записи (`cancel_recording`) до выключения серверов (`lib.rs`, ~:5499) | Чтение кода, тесты раннера |
| **CONC-03a** | Мьютекс `state` удерживался до 10 с — на всё ожидание старта WASAPI; `stop()`/`cancel()` блокировались | Лок скоупится: проверка → отпускание → ожидание без лока (`audio_recorder.rs:484-497`) | Дифф + анализ |
| **CONC-03b** | Теоретическая гонка двойного старта после снятия лока | Ре-чек под повторным локом: `try_send(RecorderCommand::Cancel)` + `drop(worker)` + `Err("Already recording")` (:543-560); воркер сам отменяется и по разрыву канала (`Disconnected => Cancel`, :896) | Дифф + чтение воркера |

## 6. Принятые остатки

1. **INFRA-01** — плейсхолдерный SHA-256/размер в `release-manifest-1.2.0.json` (`published: false`) до физической сборки инсталлятора; позиция задокументирована в ADR-033.
2. **Runtime E2E** не выполнялся (требует железа пользователя). Рекомендуемый чек-лист: онбординг-тур (5 шагов), игровой режим при активной записи, длинная диктовка >45 с через облако, fallback облако→локальный, тосты копирования DE/FR/PT, двойной старт записи.
3. **SEC-01** — runtime-подтверждение (Miri/ASan) не выполнялось: исправление верифицировано статически и ACL-тестом.

## 7. Рекомендации

1. **Перед публикацией релиза:** сгенерировать реальные `sha256`/`size` инсталлятора, выставить `published: true`; обновить winget-манифест после публикации GitHub Release.
2. **Прогнать E2E-чек-лист** (раздел 6.2) на целевой машине перед раздачей сборки.
3. **Зафиксировать рабочее дерево коммитом** (все правки аудита и WIP в настоящее время незакоммичены; версия по решению остаётся 1.2.0).
4. **Опционально:** прогнать `cargo miri test limited` по модулю `secure_storage` для закрытия вопроса SEC-01 на уровне рантайма.
