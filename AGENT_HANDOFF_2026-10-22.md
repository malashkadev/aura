## 2. Что именно исправлено

### 2.1. Экспорт настроек: нативный диалог «Сохранить как»

**Проблема:** фронтенд формировал `Blob`, создавал ссылку с `download` и инициировал скачивание. Файл попадал в папку загрузок по умолчанию, пользователь не выбирал место.

**Решение:** экспорт переведён на нативную команду Rust, которая открывает системный диалог сохранения и пишет файл только в выбранный путь.

Реализация:

- `src-tauri/Cargo.toml`:
  - добавлена зависимость `rfd = { version = "0.17", default-features = false, features = ["common-controls-v6"] }`.
- `src-tauri/src/lib.rs`:
  - добавлена команда `save_settings_backup(contents, suggested_name, dialog_title) -> Result<Option<String>, String>`;
  - размер JSON ограничен `2_000_000` байт;
  - содержимое проверяется через `serde_json::from_str` и должно быть JSON-объектом;
  - `suggested_name` очищается через `Path::file_name()`; пустое имя заменяется на `aura-settings.json`;
  - диалог вызывается в `tauri::async_runtime::spawn_blocking` через `rfd::FileDialog`;
  - если пользователь не указал расширение, добавляется `.json`;
  - при отмене возвращается `Ok(None)`, файл не создаётся;
  - запись выполняется только через `std::fs::write` по пути, который вернул нативный диалог.
- `src-tauri/build.rs`:
  - `save_settings_backup` добавлен в `APP_COMMANDS`.
- `src-tauri/capabilities/main.json`:
  - добавлено разрешение `allow-save-settings-backup`.
- `src-tauri/permissions/autogenerated/save_settings_backup.toml`:
  - сгенерированный файл разрешения, добавлен в git.
- `src/main.js`:
  - вместо `Blob`/`URL.createObjectURL`/`link.download` теперь:
    ```js
    const savedPath = await invoke("save_settings_backup", {
      contents: JSON.stringify(payload, null, 2),
      suggestedName: settingsBackupFileName(),
      dialogTitle: getTranslation("backup_title")
    });
    if (!savedPath) return;
    showStatus(getTranslation("backup_exported"));
    ```
  - при отмене диалога ложный тост «Файл настроек сохранён» не показывается.

**Важно:** не заменять это на общую команду `write_text_file(path, contents)` — это расширит поверхность записи произвольных файлов из фронтенда. Сохранять связку «диалог + запись» в одной команде.

**Известное ограничение:** нативный диалог скомпилирован и покрыт статическими проверками, но в этой сессии не был вручную открыт внутри установленного приложения. Это должен проверить пользователь при следующей установке. Если диалог окажется позади окна Aura, можно рассмотреть `rfd::FileDialog::set_parent` с главным `WebviewWindow`, но только после воспроизведения проблемы.

### 2.2. Акцент у кнопки подтверждения импорта

**Проблема:** `.modal-actions .btn-primary` принудительно переопределял primary-кнопку на прозрачный фон, серый текст и обычную рамку, поэтому «Подтвердить» визуально не отличалась от «Отмена».

**Решение:** в `src/style.css` primary-кнопка в модалках теперь использует акцентную заливку:

```css
.modal-actions .btn-primary {
  background-color: var(--accent-color);
  border-color: var(--accent-color);
  color: hsl(0, 0%, 5%);
  font-weight: 700;
}

.modal-actions .btn-primary:hover {
  background-color: var(--accent-hover);
  border-color: var(--accent-hover);
  color: hsl(0, 0%, 5%);
}
```

Это затрагивает все подтверждающие модалки, а не только импорт настроек. Это осознанно: primary-действие должно быть визуально главным.

### 2.3. Карточка первого запуска / рекомендация Base-модели

**Проблема:** карточка имела оранжевую рамку вокруг всей поверхности и выбивалась из остальных карточек; кнопки были разной высоты.

**Решение:**

- `src/index.html`:
  - убрана визуальная «тревожная» рамка (класс `first-run-card` оставлен как семантический, но CSS-правило с `border-color` удалено);
  - добавлен компактный акцентный SVG-иконка микрофона в `.first-run-heading`;
  - действия перенесены в общий `.card-actions`;
  - кэш-барьер обновлён: `style.css?v=2.0.17` и `main.js?v=2.0.17`.
- `src/style.css`:
  - `.first-run-heading` — flex-строка с иконкой и заголовком;
  - `.first-run-icon` — 20×20 px, цвет `var(--accent-color)`;
  - `.first-run-card .field-hint` — без лишнего верхнего отступа;
  - `.card-actions` — общий контейнер действий;
  - `.card-actions .btn` — высота 36 px, `padding: 0 16px`, `font-size: 0.85rem`, `margin-top: 0`;
  - убрана оранжевая рамка `.first-run-card`.

Визуально проверено в статическом превью: карточка теперь использует стандартную поверхность `.card`, иконка акцентная, кнопки выровнены по высоте, подсказка встроена в сетку.

### 7.1. Обязательное: тест пользователя

Пользователь должен установить новый NSIS-установщик и проверить:

1. **Экспорт настроек**
   - открывается системный диалог «Сохранить как»;

   - файл появляется именно там;
   - при отмене диалога нет ложного уведомления об успехе.
2. **Импорт настроек**
   - после выбора файла открывается окно подтверждения;
   - кнопка «Подтвердить» оранжевая, с тёмным текстом;

## 8. Жёсткие ограничения и gotchas

1. **Не пушить и не публиковать без явного разрешения пользователя.** Текущая политика: сначала установка и тест, потом публикация.
2. **Не повышать версию.** Остаётся `1.2.0`; не делать `1.2.1` без отдельного решения.
3. **Не менять `published: false`** в `release-manifest-1.2.0.json` без отдельного решения и изменения тестовой политики.
4. **Не возвращать `gpu_accel_dml_*`.** В 1.2.0 оставлены `history_engine_whisper` и `history_engine_parakeet`; DML-поля удалены осознанно.
5. **Не возвращать `whisper_keep_in_memory`** — мёртвое поле удалено.
6. **API-ключи никогда не экспортируются.** `buildSettingsBackup` вырезает секреты; не ослаблять.
7. **Импорт/экспорт остаётся фронтенд-ориентированным.** Нативный бэкенд отвечает только за диалог сохранения и запись выбранного файла; не добавлять отдельный нативный импорт настроек без необходимости.
8. **Не заменять `save_settings_backup` на общую запись файла по пути из фронтенда.** Это снизит безопасность.
9. **Любое изменение `src/**` или `src-tauri/**` требует пересборки.** Фронтенд встраивается в бинарник.
10. **`website/*.exe` не коммитится**, но должен лежать в `website/` для Vercel (см. `.vercelignore`).
11. **`npm.ps1` заблокирован execution policy.** Использовать `npm.cmd` (например, `npm.cmd run check`).
12. **Многострочный `node -e` через PowerShell ломается.** Для скриптовых правок создавать временный `.mjs` в `C:\Windows\Temp\opencode` и запускать `node <file>`.
13. **Сборка завершается кодом 1 без updater-ключа.** Оба бандла при этом создаются. Не считать это ошибкой кода.
14. **Authenticode-подпись отсутствует.** Установщик `NotSigned`; SmartScreen может предупреждать.
15. **Line endings:** Git может предупреждать `LF will be replaced by CRLF`. Это нормально; не запускать массовую нормализацию.
16. **Локальный тег — lightweight и локальный.** Если он уже был бы запушен, перемещение потребовало бы force-push. Сейчас remote-тега нет.
17. **Не путать `COMMANDS_METADATA` с удалёнными `commands_guide_*`:** `COMMANDS_METADATA` используется в `renderSupportedCommandsGuide`.
18. **Не добавлять второй `mod tests` в `logger.rs`.**
